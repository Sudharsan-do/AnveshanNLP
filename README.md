# AnveshanNLP — Multilingual Hindi & Hinglish 56-Class Intent Classification

End-to-end 56-class conversational intent classification system for **Hindi (Devanagari)**, **Hinglish (Romanized Hindi)**, and **code-switched Mixed** queries under noisy ASR conditions and a strict **≤ 300M active parameter** constraint.

---

## 1. Pipeline Overview & Architecture

```
                         ┌──────────────────────────────────────────────────────────┐
                         │                Raw Query (Hindi / Hinglish / Mixed)      │
                         └──────────────┬───────────────────────────┬───────────────┘
                                        │                           │
                         NFKC + Whitespace Clean     ASR Normalization + xlit_word_dict
                                        │                           │
                                        ▼                           ▼
                         ┌──────────────────────────┐ ┌─────────────────────────────┐
                         │  l3cube-pune/hing-roberta│ │  TF-IDF char_wb (1..5)      │
                         │  -mixed (models/best)    │ │  30,802 features            │
                         │  278,086,712 params      │ │  + 3-Fold Calibrated        │
                         └──────────────┬───────────┘ │  LinearSVC (1,724,968 params│
                                        │             └─────────────┬───────────────┘
                                        │ P_XLM                     │ P_SVC
                                        └──────────┬────────────────┘
                                                   ▼
                         ┌──────────────────────────────────────────────────────────┐
                         │ Script-Adaptive Geometric Fusion (Log-Space PoE, ε=0.01) │
                         │   Latin: 0.52·XLM + 0.48·SVC                             │
                         │   Dev  : 0.32·XLM + 0.68·SVC                             │
                         │   Mixed: 0.45·XLM + 0.55·SVC                             │
                         └─────────────────────────┬────────────────────────────────┘
                                                   ▼
                         ┌──────────────────────────────────────────────────────────┐
                         │ Tail Calibration & Class 55 (Out-of-Scope) Fallback      │
                         │   Multipliers: 55×1.30, 53×1.15, 12×1.15                 │
                         │   OOS_CONF rescue + low-confidence OOS guard (in UI)     │
                         └─────────────────────────┬────────────────────────────────┘
                                                   ▼
                                         submission.csv (4,912 rows)
```

### Key Components
- **[aavesham_v2.ipynb](aavesham_v2.ipynb)**: Fine-tunes `l3cube-pune/hing-roberta-mixed` (`XLMRobertaForSequenceClassification`) on 16,936 training queries plus 20,702 phonetic-noise augmented Hinglish rows, producing the `models/best` checkpoint.
- **[nlu_pipeline.ipynb](nlu_pipeline.ipynb)** (generated by [build_updated_best_notebook.py](build_updated_best_notebook.py)): Fits a 3-fold Platt-calibrated `LinearSVC` on transliterated character $n$-grams, runs batch inference with `models/best`, applies script-adaptive geometric fusion and tail calibration, and writes `submission.csv`.
- **[demo_ui/](demo_ui/README.md)**: Local interactive web workbench (`server.py` + `inference_engine.py`) with live multi-script robustness testing, Class 55 fallback controls, latency breakdown, and parameter auditing.

## 2. Cross-Script (Hindi ↔ Hinglish) & Class 55 (Out-of-Scope) Handling

### Script Covariate Shift Mitigation
Training and test splits exhibit a sharp script distribution flip:

| Split | Devanagari | Latin (Hinglish) | Mixed |
| :--- | :---: | :---: | :---: |
| **Train (`16,936`)** | 61.13% | 33.33% | 5.54% |
| **Test (`4,912`)** | 32.65% | 64.21% | 3.14% |

To prevent the model from overfitting to Devanagari:
1. **Dual-Path Normalization**:
   - **Transformer (`hing-roberta-mixed`)**: Receives light NFKC + whitespace-collapsed text (`clean`) so native Hinglish spelling and subwords remain intact.
   - **Lexical (`LinearSVC`)**: Applies `clean_asr` (collapses elongated characters like `soooong` → `song` and normalizes ASR shorthand such as `kia`→`kya`, `mjhe`→`mujhe`, `h`→`hai`, `plz`→`please`, `kr`→`karo`, `thnx`→`dhanyavad`) followed by word-level Devanagari-to-Latin transliteration via the 6,782-entry domain lexicon (`data/xlit_word_dict.json`), projecting all scripts into a shared Romanized character $n$-gram space.
2. **Phonetic Noise Augmentation (`aavesham_v2.ipynb`)**: Generates noisy Hinglish variants from Devanagari `transliterated_text` using 23 phonetic substitution rules (`aa`↔`a`, `ee`↔`i`, `oo`↔`u`, `kh`↔`k`, `ph`↔`f`, `w`↔`v`, etc., at `NOISE_P = 0.2`).
3. **Script-Stratified Sampling & Weighting**:
   - Transformer training uses a `WeightedRandomSampler` targeting `32%` original Latin, `33%` augmented Latin, `30%` Devanagari, and `5%` Mixed per epoch.
   - `LinearSVC` applies a **2.0× sample weight** to Latin training queries.
4. **Script-Adaptive Geometric Gating**: Combines probabilities in log-space ($\log P_{\text{ens}} = g(s)\log(P_{\text{XLM}} + 0.01) + (1 - g(s))\log(P_{\text{SVC}} + 0.01)$) with `g('latin') = 0.52`, `g('devanagari') = 0.32`, and `g('mixed') = 0.45`.

### Class 55 (Out-of-Scope / Catch-All) Handling
- In [data/verified_class_meanings.json](data/verified_class_meanings.json), **Class 55** (`1.47%` of train, `249` samples) has **30.72% purity**, acting as a composite catch-all for `play_podcasts`, `play_game`, `alarm_query`, and Out-of-Scope (OOS) queries.
- **Training**: Class imbalance (`84` to `1,224` samples across 56 classes) uses power-scaled weights `(max_count / count)^0.5`, while pinning `w[55] = 1.0` to avoid over-predicting the noisy bucket.
- **Inference & Fallback**:
  - `aavesham_v2.ipynb` introduces `OOS_CONF = 0.50`: when raw `argmax == 55` and confidence `< 0.50`, it rescues the query by reassigning to the 2nd-best intent.
  - `nlu_pipeline.ipynb` applies post-fusion tail calibration multipliers (`55 × 1.30`, `53 × 1.15`, `12 × 1.15`) to restore tail recall.
  - `demo_ui` exposes both `OOS_CONF` rescue and a configurable low-confidence OOS guard (`0.22` default) that routes low-confidence out-of-domain utterances to Class 55.

## 5. Step-by-Step Instructions to Reproduce `submission.csv`

### Prerequisites
- Python 3.10+ (repo uses `./venv/bin/python`) with `torch`, `transformers`, `datasets`, `scikit-learn`, `pandas`, `numpy`, `scipy`, `nbformat`.
- To retrain `models/best` from scratch, a GPU environment (e.g., Kaggle 2× T4) is recommended for `aavesham_v2.ipynb`.

### Step 1: Train the Transformer Backbone (`models/best`)
1. Open and run all cells in [aavesham_v2.ipynb](aavesham_v2.ipynb) (uses root `train.csv` with `transliterated_text` and `test.csv`).
2. Copy the trained checkpoint directory (`indicbert_v2_out/best`) into `models/best/` at the repository root so `models/best/model.safetensors`, `config.json`, `tokenizer.json`, and `tokenizer_config.json` are present.

### Step 2: Run the Final Ensemble & Generate `submission.csv`
Open and execute all cells in **[nlu_pipeline.ipynb](nlu_pipeline.ipynb)** (audits the ≤ 300M parameter budget, trains the 3-fold Calibrated `LinearSVC`, runs `models/best` inference, applies log-space geometric gating + tail multipliers `55×1.30`, `53×1.15`, `12×1.15`, and writes `submission.csv`):

```bash
./venv/bin/jupyter nbconvert --to notebook --execute --inplace nlu_pipeline.ipynb
```

*(Note: [build_updated_best_notebook.py](build_updated_best_notebook.py) is the generator script for the linear-blend `0.82722` predecessor; [nlu_pipeline.ipynb](nlu_pipeline.ipynb) contains the final `0.83010` geometric fusion pipeline.)*

### Step 3: Verify Benchmark Scores & Submission Integrity
```bash
./venv/bin/python evaluate_submission.py submission.csv
```

Expected output confirms `4,912` rows, `56 / 56` predicted classes, `0` nulls, and `0.83010` High-Confidence Macro-F1.

### Step 4 (Optional): Launch the Interactive Demo UI
```bash
./venv/bin/python demo_ui/server.py --port 8000
```
Open **http://127.0.0.1:8000** in your browser.
